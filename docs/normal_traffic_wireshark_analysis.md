# Аналіз дампу `normal_traffic.pcap` (tshark)

## Загальні метрики захоплення

### Команди

Загальна статистика за весь дамп (тривалість, кількість кадрів і байтів):

```bash
tshark -r normal_traffic.pcap -q -z io,stat,0
```

Розподіл кадрів і байтів по 10-секундних інтервалах:

```bash
tshark -r normal_traffic.pcap -q -z io,stat,10
```

Мінімум, максимум і середнє значення довжини кадру (`frame.len`):

```bash
tshark -r normal_traffic.pcap -T fields -e frame.len | awk '{sum+=$1; n++; if($1<min||n==1)min=$1; if($1>max)max=$1} END{printf "count=%d min=%d max=%d mean=%.1f\n", n, min, max, sum/n}'
```

### Результат

| Параметр | Значення |
|----------|----------|
| Тривалість | ~64,7 с |
| Пакетів (frames) | 2239 |
| Обсяг | ~802 КБ (822 288 байт) |
| Середня частота | ~34,6 пак/с |
| Середній розмір кадру | ~367 байт |
| Мін. / макс. розмір кадру (`frame.len`) | 42 / 8222 байт |

Розподіл навантаження по 10-секундних інтервалах: від ~285 до ~392 пакетів на інтервал (нерівномірна активність по часу).

## Ієрархія та основні протоколи

### Команди

Ієрархія протоколів (`-z io,phs`):

```bash
tshark -r normal_traffic.pcap -q -z io,phs
```

Частота повних стеків у полі `frame.protocols`:

```bash
tshark -r normal_traffic.pcap -T fields -e frame.protocols | sort | uniq -c | sort -rn | head -25
```

### Результат

З виводу **io,phs**:

- **Ethernet** — усі кадри.
- **IPv4** — 2233 кадри (~822 КБ); решта — **ARP** (6 кадрів, службовий L2/L3).
- **TCP** — 1796 кадрів (~637 КБ): переважно **TLS** (зашифрований веб/API тощо), є сегментація TCP.
- **UDP** — 437 кадрів (~165 КБ):
  - **DNS** — 276 кадрів;
  - **QUIC** — 26 кадрів (HTTP/3-подібний трафік);
  - інший UDP-пейлоад (у статистиці як `data`) — великі сесії до порту 443 по UDP

Підрахунок за **стеком полів** `frame.protocols`: найбільше `eth:ip:tcp`, далі `eth:ip:tcp:tls`, потім `eth:ip:udp:dns`, QUIC, окремі ARP.

## Типи трафіку

### Команди

Підрахунок пакетів за display filter (`-Y`):

```bash
for f in tcp udp dns tls quic arp icmp; do
  c=$(tshark -r normal_traffic.pcap -Y "$f" -T fields -e frame.number | wc -l)
  echo "$f: $c"
done
```

### Результат

| Фільтр | Пакетів (прибл.) | Коментар |
|--------|------------------|----------|
| `tcp` | 1796 | Основний транспорт, багато до порту **443** |
| `tls` | 776 | Зашифровані з’єднання поверх TCP |
| `udp` | 437 | DNS, QUIC, UDP/443 |
| `dns` | 276 | Запити/відповіді DNS |
| `quic` | 26 | QUIC (часто пов’язано з вебом) |
| `arp` | 6 | Дозвіл адрес у локальній мережі |

## IP-адреси

### Команди

Статистика IPv4-вузлів (`-z endpoints,ip`):

```bash
tshark -r normal_traffic.pcap -q -z endpoints,ip
```

Розмови між IP (`-z conv,ip`):

```bash
tshark -r normal_traffic.pcap -q -z conv,ip
```

TCP-сесії (порти, обсяги):

```bash
tshark -r normal_traffic.pcap -q -z conv,tcp
```

UDP-сесії:

```bash
tshark -r normal_traffic.pcap -q -z conv,udp
```

### Результат

**Локальний хост:** `192.168.1.9` — джерело/отримувач майже всього IPv4-трафіку (2233 пакети за статистикою endpoints).

**Найактивніші зовнішні вузли** (за кількістю кадрів у IP-розмовах), наприклад:

- `76.76.21.22`, `66.33.60.129` — великі обсяги (CDN/хостинг).
- `1.1.1.1` (Cloudflare DNS) — багато невеликих обмінів (**DNS**, порт 53).
- Адреси з діапазонів **104.18.x.x**, **172.64.x.x**, **162.159.x.x** — характерні для Cloudflare та подібних сервісів; з’єднання переважно на **443/TCP** та **443/UDP** (QUIC).

**TCP:** багато коротких і довгих сесій до **:443** (TLS). Окремо виділяється трафік до **149.154.167.41:443** (діапазон, пов’язаний з месенджерами на кшталт Telegram).

**UDP:** помітна сесія `192.168.1.9` ↔ `172.64.155.209:443` по UDP (великий обсяг байт) — узгоджується з QUIC/HTTP3-подібним використанням порту 443 на UDP.

## Висновок

Дамп відображає **типовий «нормальний» вихідний веб-клієнтський трафік**: переважно **HTTPS (TLS на TCP)** і **DNS**, з елементами **QUIC/UDP 443**, плюс незначний **ARP**. Розміри кадрів варіюються від мінімальних службових до **>8 КБ** (ймовірно фрагментація/MTU або великі відповіді).
